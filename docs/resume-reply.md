# 简历与回复助手（0.8.2）

## 根据简历生成提示词

1. 在岗位页进入 **AI → 简历生成提示词**。也可在 BOSS 沟通页右上角的个人菜单打开 **简历与提示词**。
2. 导入 PDF、DOCX、TXT 或 Markdown，或直接粘贴简历文字。文件最多 8 MB，PDF 最多 20 页，正文最多 5 万字。
3. 核对提取文字的顺序和完整性，填写主投岗位、可拓展方向、谨慎方向、经历边界、城市、薪资意向及其他明确限制。未填写的信息不会自动补造；谨慎方向只提示核查职责，不凭标题直接过滤。
4. 点击 **生成三组提示词**，分别查看筛选、招呼和回复预览。模板根据简历原文生成，不在此步骤调用模型。可以直接修改预览文字。
5. 选择要应用的提示词，勾选已经核对事实，再点击 **应用选中的提示词**。投递正在运行时应先停止。

应用只更新所选功能的 `prompt`，保留模型、启用开关、筛选分数、招呼条数及延迟参数。需要实际启用筛选或招呼时，仍使用原来的 AI 配置开关。

## 本机求职方案

同一个文件入口也支持求职方案 `.json`，可一次填写简历和各类意向。它只加载表单，导入后点击“生成三组提示词”、核对预览并应用。它不会导入模型、密钥、开关或运行参数，不会自动开启投递和回复。普通配置 JSON 继续使用原配置导入入口。

方案格式如下。文件只应保存在本人控制的位置，避免随公开代码或安装包发布：

```json
{
  "kind": "boss-helper-resume-plan",
  "version": 1,
  "resumeText": "填写不少于40字的真实简历正文……",
  "goals": {
    "roles": "主投岗位",
    "adjacentRoles": "根据实际职责评估的拓展方向",
    "cautionRoles": "需要额外核查的岗位方向",
    "evidenceNotes": "例如生产集群与个人实验规模不同，直管人数与跨团队协调人数不同",
    "city": "",
    "salary": "",
    "notes": "其他明确意向；未确认的事项不要写成硬性限制"
  }
}
```

简历正文最多5万字，各意向字段最多2000字。导入会默认隐藏简历正文的手机号、邮箱和证件号，且只读取上述已知字段。生成后的提示词要求按生产、客户项目、个人实践等证据层级评分和表达；不能保证模型永远正确，仍需预览核对。正向各维度最多合计100分，最终仍使用加分总和减扣分总和及原有阈值。

**恢复上一次提示词** 对当前预设生效，只恢复上一次应用前的提示词内容，不把模型和开关退回旧设置。仅保留最近一次替换备份。

“保存简历到本机”是单独操作，不要求保存原文件。清除本机简历不会修改已经应用的提示词；若要清除其中的简历信息，也需要恢复或编辑这些提示词。

扫描图片式 PDF 暂不识别文字，会明确提示先 OCR；旧 `.doc` 请另存为 `.docx`。加密文件先去掉密码。表格、分栏和部分字体可能影响提取顺序，必须以预览为准。

## 筛选分数、待确认和请求耗时

筛选每次运行时都会追加校验规则，不要求覆盖浏览器中已经保存的个人提示词。简历未提及或未证明某能力只能视为未知，不能据此扣分或单独阻断已达到分数阈值的岗位。未知技术项列入“AI筛选待核实提示”，便于后续沟通；这不代表本人没有能力，也不允许招呼宣称已经掌握该技术。明确的个人条件冲突和实际职责不匹配继续评分过滤。

评分会检查正整数和总额、去除完全重复的理由。超出100分上限会转人工核对；原有筛选阈值和净分算法保留。

## 本机专属简历来源

维护安装可在 `private/resume-context.json` 放一份上述求职方案JSON。后台只读取这一个固定文件，返回简历正文；运行时更新旧摘要，保留原求职意向和模型设置，不重复附加整份简历。该目录被Git忽略，打包脚本不会把它放入公开安装ZIP，也不增加网页可访问资源。

发现本机专属文件时默认启用，面板可用“使用本机专属简历作为运行时事实”开关停用，按当前BOSS账号记住。清除输入与浏览器保存的简历会同时停用本机来源，但不删除安装目录原文件；已经应用的提示词仍需单独恢复或编辑。确认并应用不同简历时，会停用旧本机文件对新简历的覆盖。普通安装没有此文件时，继续使用浏览器保存的简历与提示词。

DeepSeek官方接口的筛选与招呼请求会使用非思考模式。按[官方接入说明](https://api-docs.deepseek.com/quick_start/agent_integrations/)，V4.1 Flash使用 `deepseek-flash`，地址 `https://api.deepseek.com`；非思考参数依据[官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。不会自动更改已经选择的模型，也不会给未知第三方代理添加专属参数。

岗位筛选或招呼的每次 AI 调用（含重试）最多等待60秒；模型设置更短则使用更短时间。格式错误可在0.5秒后重试一次，其他快速暂时故障也最多一次；超时、鉴权、配额或持续输出错误会停止本轮，避免每个岗位重复长等待。此限制不改变手动模型测试和回复草稿的原超时设置。

日志中的“AI请求开始／完成／重试／缓存命中”会显示预算、实际耗时和上下文/输出字符数，可用来区分模型耗时与平台冷却。时间预算限制失败等待，不保证所有模型都能在预算内完成。纯推理内容或截断结果不能代替最终结果；不会因此自动提交消息。

## 回复草稿

1. 在 **回复助手** 选择模型。默认沿用招呼模型，未配置时沿用筛选模型；也可单独选择回复模型。
2. 保持页面打开。助手只处理消息连接建立后到达的新文字消息，不拉取旧聊天，不作为关掉浏览器后继续运行的服务。
3. 默认手动点击 **生成回复草稿**。需要收到消息就准备草稿时，勾选 **收到新消息时自动起草**。这不会自动发送。
4. 选择会话，核对接收人、近期问题、草稿和待确认事项，可以修改草稿。
5. 勾选 **我已核对接收人、最新消息和回复内容**，点击 **确认并发送这一条**。发送前沿用原消息延迟；投递仍在运行时需先停止投递，再继续回复辅助。

新问题会使旧草稿失效。停止辅助或已识别的手动输入会暂停辅助并取消未发布内容；也可对单个会话点击“人工接管”。重新启用需要点击“继续回复辅助”或针对该会话手动起草。

未知的薪资、离职、到岗、面试时间、接受条件和附件发送情况不应由模型承诺，都会留给本人核对。AI 草稿并不保证事实完全正确。

同一条 HR 消息不会重复提交。若已尝试发布但未收到可靠确认，会显示 **请核对发送结果**；先在 BOSS 原聊天核对，程序不会自动补发。

收到的最近对话只保存在页面内存中，刷新后消失。若没有收到新消息，请先核对页面消息连接状态。模型请求失败会暂停自动起草，检查配置后再继续。

## 数据去向

文件解析和模板生成均在本机完成。应用后的简历提示词，以及实际起草所需的近期对话，会发给本人配置的 AI 服务。原始文件不上传。详见 [数据与网络说明](../PRIVACY.md)。

PDF 提取使用固定随包的 [Mozilla PDF.js](https://github.com/mozilla/pdf.js)，接口依据 [PDF.js 文档](https://mozilla.github.io/pdf.js/api/draft/api.js.html)。许可证与文件校验信息随包保留。
