# 个人维护工程

项目以已经验证过的本地扩展 0.5.2 为基础，当前维护分支为 `personal/edge-0.7.1`。它拥有独立名称、版本、图标、欢迎界面、版本面板、反馈地址和打包流程。

## 文件分工

| 位置 | 用途 |
| --- | --- |
| `src/project.json` | 名称、版本、维护者、仓库和发行说明 |
| `src/project-config.js` | 随包提供的配置，关闭外部公告轮询 |
| `src/ui/` | 个人版欢迎菜单、版本面板、简历与回复助手 |
| `src/features/` | 通信与工作流辅助，以及简历提示词、文件解析、回复状态和运行时适配 |
| `src/edition.cjs` | 对冻结的运行时应用个人版调整；锚点不匹配就停止构建 |
| `scripts/` | 构建、离线检查、图标生成和 ZIP 打包 |
| `vendor/` | 冻结的编译运行时模板、原清单及 SHA-256 来源记录 |
| `third_party/pdfjs/` | 固定为 6.4.299 的 PDF.js 兼容构建、CMap、字库、许可证和逐文件 SHA-256 |
| 根目录的 `boss.js` 等 | 生成后的可加载扩展文件 |

优先编辑 `src`，再执行构建。直接修改根目录生成文件会在下一次构建时被覆盖，检查程序会发现源文件与生成物不一致。

`vendor` 中仍是原项目衍生的编译代码，不是完整 Vue/WXT 源码。本工程可重复构建和维护当前发行版，但不声称已经恢复或重写全部上游源码。大规模界面或平台适配重构，应另行迁移原生源码并逐项移植此前修复。

## 兼容性

保留现有配置键、预设键、页面元素名称和通信命名空间，避免更新后清空用户设置。浏览器权限与原可用版保持一致；仅将打包的 `libs/pdfjs/*` 加入既有 BOSS 域名匹配的可访问资源。新版本不读取原作者 `net-conf.json`，不创建五分钟公告轮询，也不从原商店覆盖自己的版本。

原作者的 About、赞赏、问卷、商店、头像和提示词帮助入口已从实际运行文件移除。版权、许可证和历史来源仍保存在许可证、NOTICE、冻结模板及历史记录里。

## 发布与回退

确认构建和测试通过后，使用个人版本标签，例如 `v0.7.1-personal.20261015`。不改写旧提交、旧标签或远程 `main`。

停止任务后可以用 `git switch` 切换到已保存的旧维护分支，再重新加载扩展。构建生成的未提交文件应先保存，避免覆盖需要保留的改动。源码打包用已提交的 Git 快照；安装包仅包含运行所需文件、安装说明、版权和校验记录。
