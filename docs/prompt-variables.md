# 提示词变量

在提示词中用 `{{ 变量路径 }}` 插入岗位数据。当前岗位列表原始字段位于 `data`，例如：

| 变量 | 内容 |
| --- | --- |
| `{{ data.jobName }}` | 职位名称 |
| `{{ data.salaryDesc }}` | 薪资描述 |
| `{{ data.brandName }}` | 公司名称 |
| `{{ data.jobExperience }}` | 工作经验要求 |
| `{{ data.jobDegree }}` | 学历要求 |
| `{{ data.cityName }}` | 城市 |
| `{{ data.areaDistrict }}` | 行政区 |
| `{{ data.bossName }}` | 招聘者姓名 |
| `{{ data.bossTitle }}` | 招聘者职称 |
| `{{ data.skills }}` | 技能列表 |

可用字段以当前 BOSS 页面实际数据为准。缺失值不会自动补成事实，可通过 Prompt 测试和岗位日志检查。

启用高德距离筛选后，可使用配置面板已经列出的距离变量，例如 `{{ amap.straightDistance }}`。没有初始化地图功能时，不应假设距离数据已存在。

AI 招呼在 AI 配置里选择两条或三条。维护版先整体生成、校验，再依次发送；停止任务后不会继续发送剩余消息。保持简历事实和已有约束，不要让模型补造经历。

## 简历生成的提示词

“简历生成提示词”在本地把核对后的简历和意向加入三组模板。筛选继续输出 `negative` / `positive` JSON，招呼继续输出两条或三条字符串数组，均适配原有工作流。应用后保留已选模型、筛选阈值和消息条数。

简历正文中的 `{{`、`}}` 会转换为全角括号，避免把简历文字误当成岗位变量。

## 回复提示词变量

回复助手支持 `{{ hrMessage }}`（最新 HR 问题）、`{{ conversation }}`（本页已接收的最近对话 JSON）、`{{ resumeText }}`（当前已确认的简历）和 `{{ jobData.字段 }}`。无法关联到本页已知岗位时，岗位字段为空；不额外请求岗位或历史消息。

回复模型需输出 `{"reply":"中文回复草稿","confirm":["需要本人确认的事项"]}`。无待确认事项时使用空数组。输出只进入待审核区，模型调用本身不会发送聊天消息。
