# boss-helper（我的维护版）

Nginx1 的 BOSS 直聘求职助手，当前个人版本 **0.8.7**。支持简历导入生成提示词、人工确认的回复草稿、岗位筛选、两条或三条招呼、配置预设和投递记录。

项目仓库为 [Nginx1/boss-helper](https://github.com/Nginx1/boss-helper)。个人维护分支为 `personal/edge-0.8.7`，版本标签为 `v0.8.7-personal.20261110`。

本版使用自己的名称、图标、版本信息、欢迎说明和反馈入口；不读取原作者的公告、问卷或扩展商店更新。“关于&赞赏”标签页已移除。

## 安装

本机现有安装目录仍为 `D:\Download\boss-helper-0.5.2-edge`。停止投递，在 Edge 扩展页重新加载，再刷新 BOSS 页面即可使用新版本。保持原目录有助于沿用现有配置。

安装 ZIP 的新装和配置迁移见 [安装说明](docs/install.md)。

## 简历与回复助手

在岗位页的 **AI → 简历生成提示词 / 回复助手** 打开。沟通页可通过右上角个人菜单打开相同功能。

- 支持 PDF、Word（DOCX）、TXT / Markdown 和粘贴文字。本地提取后核对简历及意向，再预览、修改并应用筛选、招呼和回复三组提示词。扫描 PDF 需要先识别文字；旧 DOC 请另存为 DOCX。
- 可载入本机求职方案 JSON，分别填写主投、可拓展和谨慎方向及经历边界；按实际职责评估，区分生产与个人实践、直管与项目协调，不拼接跨项目规模与成果。个人方案不随公开代码或安装包提供。
- 应用时保留模型、启用开关、筛选分数、招呼条数与发送间隔，并备份当前预设的旧提示词，可恢复上一次替换。
- 回复助手接收页面连接后到达的新文字消息，只生成草稿。你核对接收人和内容、勾选确认后，才按原消息延迟提交一条回复。默认不自动起草，更不会自动发送。
- 新消息、停止辅助、人工接管及账号变化会使旧草稿失效。投递运行时不能同时确认回复；不自动拉取历史聊天。

完整操作与边界见 [简历与回复助手说明](docs/resume-reply.md)。

AI 筛选启用时，先核对实际核心职责与双方证据，再按及格线筛选。直接匹配和有真实经历支持的可迁移岗位均可通过。职责不符直接跳过。核心信息不足或不可替代的硬性条件待核实时，转人工确认。投递记录包含分数、理由和匹配类型，投递前再次核验有效通过记录。

在薪资范围中勾选「不限月薪上限」后，只显示月薪下限。岗位月薪区间达到该下限即可进入后续筛选，例如下限 18K 时，15–25K 和 30–60K 均符合。选择按小时或按天计薪的岗位时，使用各自的高级区间。

偶发 AI 超时、格式错误或岗位处理异常会跳过当前岗位，继续下一个。连续 3 个岗位处理失败时暂停本轮，正常处理一个岗位就重新计数。平台频率限制、登录失效、安全验证及模型鉴权、余额或限流等明确的阻断会立即暂停。

从 0.8.4 开始，**日志 → 投递记录** 会显示最近处理结果，并可导出 CSV 或 JSON。记录包含岗位信息、取得的岗位描述、投递状态、处理环节、原因、AI 分数及理由。平台确认投递后，招呼出错仍显示已投递。提交后缺少平台确认会单独标记。

## 构建与检查

需要 Node.js 22.13 或以上，无需安装 npm 依赖。PDF.js 解析器和字库已固定版本随工程提供，不使用 CDN。

```powershell
node scripts/build.cjs
node scripts/test.cjs
node scripts/package.cjs
```

构建默认更新根目录可加载文件。打包产生 `dist/boss-helper-personal-0.8.7.zip`。六组离线检查覆盖通信恢复、招呼、简历与回复、构建一致性、岗位筛选、连续失败控制及日志导出。请求和消息均使用模拟数据。

## 维护

修改名称、版本和项目地址从 `src/project.json` 开始。自己的界面、配置及辅助源码在 `src`；构建和打包工具在 `scripts`；来源记录和冻结运行时在 `vendor`。

本工程是已打包扩展的独立维护工程，冻结运行时仍为编译代码；它不是完整原生 Vue/WXT 源码重写。此前已验证的通信、缓存、超时与多条招呼修复保留在发行版中。详细说明见 [维护文档](docs/maintenance.md)、[更新记录](CHANGELOG.md)、[提示词变量](docs/prompt-variables.md) 和 [数据与网络说明](PRIVACY.md)。
